# main 分支验收指南

本指南用于验证 `main` 分支实际构建的 XPI，包含 U1–U10 场景。每轮在对应变更的 PR 或独立验收记录中保存提交、包身份与实际结果；不沿用其他提交的通过结论。未执行项记 `NOT PERFORMED`，仅可选且条件缺失的项目记 `NOT APPLICABLE`。

## 1. 固定 main 构建与边界

每轮记录 `main` 完整提交 SHA、XPI SHA-256、Neo 与 Zotero 完整版本、操作系统、键盘布局、输入法、profile 和数据目录，以及是否为持久安装。目标范围是当前最新稳定 Zotero；包兼容范围以同一提交的 `manifest.json` 为准。

从要验证的 `main` 提交构建并检查：

```bash
git rev-parse HEAD
npm ci
npm run verify
sha256sum zotero-neo.xpi
```

Windows 可使用仓库的 PowerShell 入口：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
Get-FileHash zotero-neo.xpi -Algorithm SHA256
```

`npm run verify` 检查格式、类型、契约、构建和 XPI 成员，不代替人工验收。也可以从同一 `main` 提交的成功 CI 运行取得构建附件，获取方式见[安装与入门](GETTING_STARTED.md#获取-xpi-安装包)。

安装和更新结果只适用于记录的那个包身份。包字节变化后，记录新的提交与哈希并执行受影响的包验收；其他构建的结果不能转记为当前包的 PASS。

## 2. 建立安全的验收环境

使用新的 profile 和独立数据目录，不使用日常库、同步账户或共享数据库。官方说明：[多 profile](https://www.zotero.org/support/kb/multiple_profiles)、[数据目录](https://www.zotero.org/support/zotero_data)。

1. 关闭正在使用的 Zotero。通过实际 Zotero 可执行文件加 `-P` 打开 Profile Manager，创建具名验收 profile。例如 Linux 使用 `zotero -P`，macOS 使用 `/Applications/Zotero.app/Contents/MacOS/zotero -P`；Windows 对实际安装的 `zotero.exe` 使用 `-P`。不要把安装路径误当作 profile 路径。
2. 创建两个分别用于“干净安装”和“main 构建更新”的新 profile，名称应带本轮日期／唯一后缀，不复用临时名称。
3. 在每个验收 profile 中，通过 Zotero Settings → Advanced → Files and Folders 选择新的空数据目录，并重启。使用 **Show Data Directory** 核实实际路径。新 profile 不保证一定自动获得独立数据目录。
4. 若首次打开已显示真实资料库，立即停止操作并关闭实例，先按官方流程完成数据隔离；不导入、删除、改名或同步真实资料。
5. 不登录同步账户。只导入有授权／公有领域的 PDF，或者自己制作的测试文档。不把私人 PDF、笔记、窗口标题或剪贴板内容录进视频。
6. 使用原生 Add-on Manager 持久安装 XPI。此轮不运行 `npm run dev:start` / `npm run dev`，不混用同 ID 的临时 RDP 加载和持久包；临时加载不能证明安装／升级。

`npm run dev:setup -- --profile ...` 为已存在的开发 profile 配置 RDP，也支持未注册到 `profiles.ini` 的独立目录。工具不提供 `--data-dir` 或 `--port` 参数，也不替代上面的数据隔离和持久包验收。技术排查需要 RDP 时，另建开发 profile，遵守[开发指南](DEVELOPMENT.md#本地-zotero-gui-迭代)。

### 最小数据集

只在验收库中建立以下原生 Zotero 数据：

- 文献 A，附一份可选中文／英文文本、至少两页、至少两个原生 Outline 条目的 PDF；有条件再提供真实 Figure/Table 结构。
- 文献 B 及其 PDF，用于证明跨阅读器／主窗口目标不会串用。
- A 的两条已有笔记、B 的一条已有笔记，A/B 中各有一条同名笔记；正文包含分段和少量格式。
- 文献 C，无子笔记；一条独立笔记；两个测试集合；两个可删除的测试条目。
- 可选：已安装且可正常工作的 Better BibTeX／Translate，或一个可安全停用且有注册设置入口的测试插件。未安装时记录条件缺失，不把该项记为通过。

建立数据可以使用 Zotero 原生界面。

## 3. 安装和升级

### U1：干净安装 main 构建

1. 在干净验收 profile 中打开 Tools → Plugins／Add-ons，通过 gear 菜单选择 Install Plugin From File，安装记录过身份的 `main` XPI；按提示重启。
2. 核实插件列表中的 Neo 版本与本轮源码及包内 manifest 一致，并记录完整提交和包哈希；版本字符串相同不代表两个构建的字节相同。
3. 在主窗口条目列表的 Normal 状态下，按 `:` 打开 Command Palette；只有一个面板，输入查询和取消正常。
4. 用 `<Space>ps` 打开 Settings，查看阅读器、主窗口、笔记编辑器和本地控件对应的实际上下文；Reader 不出现 Insert，Note Insert 保留。
5. 在配置编辑器记录 `extensions.zotero-neo.bindings.schemaVersion`，核实它与本轮确切源码 `src/core/preferences.ts` 的 `BINDING_SCHEMA_VERSION` 一致。不手动修改 schema 数值制造升级结果。
6. 关闭并重启该 profile，再执行一次入口命令；没有重复面板或遗留旧代键处理。

**通过标准**：持久版本正确、默认功能入口可用、配置上下文正确、重启后只有一个当前输入处理方。单凭“插件列表显示启用”不算功能通过。

### U2：更新 main 构建并保留设置

在独立更新验收 profile 中先完成 U1，并使用当前设置界面建立以下对照：

1. 在 Reader Normal 为 `scrollDown` 添加大小写敏感的 `Q`，并显式取消默认 `j`。应用绑定，核实 `Q` 可执行、`j` 不再触发 Neo 滚动；保存实际 `extensions.zotero-neo.bindings` 值。
2. 修改一项普通行为偏好，例如关闭 Vim 风格笔记编辑，并记录其实际值；不要重置其他偏好或修改 binding schema 来制造更新结果。
3. 关闭 Reader，使用 Zotero 原生插件管理器安装本轮记录的 `main` XPI，按现场提示重启。验证重复安装当前包，或更新到另一个明确记录的 `main` 构建；两者须分别说明，不把重装称为跨版本迁移。
4. 核实提交对应的包身份、源码 schema、自定义 `Q`、`j` 的明确取消和普通行为偏好均正确；已有测试笔记、标签和分类不丢失。
5. 再次退出并重启，重复入口与配置检查，确认没有第二次重置或重复输入处理。完成后恢复本轮修改的绑定和行为偏好。

**通过标准**：安装的包身份可追溯，当前配置与用户意图保留，重启后仍一致。失败时记录修改前后的实际值，不先 Reset 掩盖问题。

### U2-R：正式版跨版本与原生更新

1. 在独立 profile 中持久安装实际公开的旧版 XPI，记录来源及哈希。使用原设置建立自定义键位、取消映射和普通偏好，并创建测试条目、笔记、标签与分类；不得用修改 schema 或版本字符串代替旧版。
2. 发布前，将已固定身份的新候选通过原生插件管理器持久安装。核对旧版到新版的迁移、设置和数据保留，完整退出再启动，确认当前包身份及单一输入处理方。另在干净 profile 验证全新安装；若测试的是同版本重装，必须如实标注。
3. 保留另一份旧版 profile 的关闭状态副本。正式 Release 和更新清单公布后，从原生插件管理器检查更新，使用其返回的更新完成下载与安装；不手动更改该插件的更新 URL，不以本地替换包代替网络升级。
4. 核对检测版本、兼容范围、真实下载来源、已安装包 SHA-256、启用与自动更新状态；按宿主提示重启，再核对第 1 步保存的设置与数据。已有 `0.2.0` 开发包也要使用真实包验证升级到更高版本，不能仅修改版本字符串模拟。

**通过标准**：旧版确实经原生更新机制发现并安装更高的正式版本，包与 Release 一致，配置及原生数据保留。网络不可达、未执行的平台或仍待重启必须单独记录，不写为 PASS。此前已由用户确认且本次未受影响的物理输入／IME 项目无需重复。

## 4. 每个交互界面和视图的一次动作

默认键位用于这一组；U2 的自定义键位和取消映射单独记录，不能把已取消的 `j` 当作默认失效。

### U3：主窗口与笔记编辑器

- 主窗口条目列表 Normal：只按一次 `s`，检查当前目标只进入 Neo 选择集一次；没有重复切换、第二个意外目标或额外条目游标移动。移动条目游标后按 `o`，只打开游标指向的条目，不借用已有 Neo 选择集；返回文库后 Neo 选择集保留。
- 用 `<Space>ss` 检查 Neo 选择集的可见／隐藏成员。用 `v` 建立可视范围，按 `Escape` 取消，不清空已有 Neo 选择集。
- 在设置中启用 **Vim-style note editing**（中文界面：**Vim 风格笔记编辑**）后打开一条测试笔记。Normal `i` 进入原生 Insert；输入并切换到另一条笔记时，新笔记条目或编辑器身份不继承旧笔记的待处理输入。使用已有笔记编辑动作或原生文本／撤销功能时，不应多出键字符或重复编辑。
- 在笔记编辑器 Insert 或原生可编辑字段中输入文字／操作剪贴板，不把这些输入当作主窗口／阅读器 Normal 命令。

### U4：阅读器主视图／次视图

1. 打开 A PDF，等待 Neo 在阅读器中的交互可用；建立水平或垂直分屏。固定窗口大小、缩放和滚动设置，拍到两侧位置。
2. 焦点在主视图 PDF 时，轻按并释放一次默认 `<C-d>`，观察一次配置预期的半页运动；次视图不移动，不出现另一个工具／面板动作。
3. 将实际焦点切至次视图后重复一次；主视图不受影响。键盘自动重复或长按不属于这个用例。
4. 在每侧执行一次 `<Space>ro` 并回到 PDF，再执行 `[s` / `]s`；当前视图变化正确，没有一次按键触发两次跳转或改变另一侧。
5. 关闭次视图，保持主视图可操作；关闭阅读器再重开，等待新视图可用后重复一个动作。
6. 用原生插件管理器禁用／启用 Neo 后，再分别观察主窗口和当前阅读器中的动作；不要同时保留临时 RDP 版本。

**通过标准**：实际焦点对应的输入处理方能解释每次动作；活跃视图、关闭／重开和禁用／启用后都只有一个当前输入处理方。只看 bridge “安装成功”或一个 overlay 的数量，不等于一次动作已被证明；若录像无法区分次数，就保留该项目未确认，并收集实际诊断，不猜 PASS。

## 5. 真正的输入法和原生键

### U5：文本输入的真实 OS IME

对 Flash 查询、批注评论文本框和 Picker 查询分别执行下列操作。使用真实键盘、真实 OS 输入法，录屏范围包含候选窗和当前输入框：

1. 输入一段能出现多个候选的拼音／其他输入法文本，不直接粘贴最终汉字。
2. 在候选窗选择一个候选并确认，确认提交内容进入当前输入框／草稿；没有提前运行 Neo 的 Enter 动作。
3. 重新进入输入法组合状态，按 Escape 取消候选；只取消输入法状态，当前 Neo 输入／工具不因此退出或保存关闭。
4. 输入法组合期间按 Backspace 删除预编辑字符，Neo 不退场、不误触快捷键。
5. 再提交文本，组合结束后才执行正常的 Neo 确认／取消；该动作恢复其正常语义。

批注评论编辑器补充：普通 `Enter` 是换行；最后一次输入后约两秒自动保存，自动保存时编辑器必须保持打开。普通 `Escape` 会保存最终草稿并关闭编辑器；Neo 停用交互、将输入交回 Zotero 原生编辑器时也会先保存最终草稿。IME 组合期间的 `Escape` 由输入法先处理，不执行编辑器的保存命令。

关闭视图或阅读器本身只释放编辑器，不会补存未保存草稿，因此关闭视图或阅读器前先按 `Escape` 保存。原生保存已经开始后，生命周期清理不会取消它；普通失焦不能作为保存保证。

验证自动保存时，保持批注评论编辑器打开，且不要按 `Escape`、也不要发生输入交接；从 Zotero 原生批注卡片或单独标明的只读持久值检查中读回已保存内容。文本框中的草稿和关闭后重开的结果不能单独证明自动保存。若无法独立读回，应把自动保存标为未确认，单独记录 `Escape` 或停用时输入交接保存的结果。

### U6：Settings 录键和浏览器输入

1. 在 Settings 搜索字段中使用真实 IME，搜索文本是提交后的内容，不把预编辑字符重建为快捷键。
2. 选择有效的动作和按键上下文，进入 **Record** 状态并发起输入法组合；Process/229 和候选确认键不能变成误记录的 Neo 命令或提前 Apply。
3. 组合结束后录入一个真实可用序列。Enter/Escape 是被记录的按键，不是隐含的 Done/Cancel。使用界面明确的 Done 或 Cancel，检查焦点返回编辑目标。
4. 验证编辑未 Apply 时实际旧绑定仍生效；明确 Apply 后才改变。取消／失败不能把待应用的草稿当作已保存。

Recorder 不是汉字编辑器；这一场景验证它让出 IME 和保持显式完成边界，不要求在 Recorder 里录入汉字字符串。

### U7：Outline 与剪贴板

- 聚焦真正的 native Outline，使用原生箭头、Tab/Shift-Tab、Enter/Return；目标仍按 Zotero 的原生行为激活。不要把 default-unbound 的 `uiConfirm` 或另一面板的 Enter 当作 Outline 默认。
- 在 Picker 查询、评论或 Note Insert 中，用自己的测试文字验证原生复制／粘贴，包括平台支持的 `<C-Insert>` / `<S-Insert>`。一次复制后在另一个安全原生字段粘贴核对内容；不以脚本直接读取／写入 clipboard 代替人体操作。
- 在 Settings binding draft 中尝试把这些 native 保留键藏到一个多键序列的后续 token，确认冲突会阻止 Apply；不要因此禁用原生功能。

**通过标准**：每个指定目标的实际 focus、IME 阶段、候选确认和原生结果可见。脚本发送 composition/keyCode229、可信 Gecko 事件或调用生产 API，都不能替代这一组人工 PASS。

## 6. 核心工作流回归

这些场景也供 S1–S6 [录屏脚本](RECORDING_GUIDE.md)引用；每次验收记录真实结果，宣传片不自动成为验收证据。


### U8：查询、历史和 native Sidebars

- 按主窗口 `/` 在可见列表中查找；`<Space>fq` / `<Space>fa` 是原生 Quick/Advanced Search，二者不混淆。
- 单集合、多个集合以及宿主支持的集合／Saved Search／Library 混合选择，都能打开 Toggle Tag Filter。候选来自当前完整视图，排除范围外标签；Quick／Advanced Search 不被清除，零结果时仍可取消当前 active tag。
- 用真实的主窗口 → 阅读器 → 标签页／PDF 位置跳转，再执行 `<C-o>` / `<C-i>`。恢复符合条件的位置，而不是复制 Neo 选择集；历史不承诺恢复缩放、布局或笔记编辑器中的文本光标。
- `<Space>ro/rm/ra/rt` 直接打开／聚焦 Outline、Bookmarks、Annotations、Thumbnails，重复操作不把目标侧栏关闭。
- `[s` / `]s` 从 PDF 和四种侧栏上下文按实际位置遍历原生完整 heading tree；Figure/Table 只在存在真实 native 数据时验收，不通过标题正则编造目标。冷 SDT 处理可有等待，不能把等待宣传为零成本。
- `<Space>rs` 在所选章节内返回真实段落，确认后定位且不改写原生 Find。依次打开章节、图表和解析对照，原有互斥界面不叠加；对照打开只准备原生结果并读取缓存，不自动上传。
- 使用包含真实图表的测试 PDF，核对 `<Space>rf` 预览不导航、确认才跳转；`<Space>re` 保存的摘录包含原图及精确 PDF 来源。再用 `<Space>rn` 整理该来源，确认生成内容、嵌图、章节及来源身份；手工修改生成笔记后重复保存相同内容，应复用原笔记且保留修改，不递归收集生成结果或新建重复图像。
- Main 与 Reader 的 `<Space>ru` 分别固定各自解析的 PDF，不混用 Main 选择与 Reader 附件。替换准备界面后关闭旧 Reader，替换界面仍在；关闭所属 Reader 只退休自己的界面。另用获准服务和测试资料核对已接纳任务在关闭面板后继续，只有明确停止才取消本地等待。

### U9：变更与可选集成

- 模块边界：在一次性 profile 中，将核心模块的 `extensions.zotero-neo.modules.<id>.enabled` 旧值设为 `false`，并请求关闭六项可选增强。新配置中 `reader-hints`、`extensions`、`references` 默认开启，`translation`、`ai-qa`、`tab-enhancements` 默认关闭。保存请求后，Neo 热重载或重开 PDF 不得切换已应用状态；完全退出并重启后应用，核心 Main、Reader、Note 与 Workspace 仍可用。
- 确认默认关闭的 `ai-qa` 不注册选择动作或 `<Space>aa`，不挂载界面 runtime、不读取凭据或发起请求；手动启用并完全重启后才提供入口。保存关闭请求后，热重载保持当前状态；真正重启后撤除入口，已存配置和成果保留。恢复默认恢复六项规范值，并显式写入 `translation=false`，不改变核心旧值、快捷键、行为偏好或 Zotero 数据。
- 翻译首次迁移：模块键缺失时，已有 provider 或用户配置保留既有使用；明确 `false` 不被覆盖。`extensions` 关闭时仍能准备依赖；取消不下载也不保存启用请求。确认后安装固定官方 2.4.8，校验身份、版本和 SHA-256；保留既有上游偏好，不静默替换其他版本。
- 用真实 provider 自动翻译公开测试文字，修订弹窗内容后保存；确认无需再次请求、只生成原生蓝色便签，重复保存同一结果不重复创建。覆盖次分屏、Reading Mode、相同原文复用与 popup／视图替换，保存位置必须来自当前 popup。重开 Reader 检查持久化及全部／批注／译文筛选；已有人工批注和原生颜色筛选不受破坏。
- 在一次性 profile 中启用 `tab-enhancements` 并完全重启 Zotero。核对位置选项为左、右、上方，默认左侧；模块启用后切换位置立即生效，当前活动视图、分组与顺序保留，Reader、PDF、Note 不重挂或重载。
- 上方模式使用 Neo 绘制的横向标签栏，原生工具栏保留。用鼠标完成最终界面提供的基本标签／分组操作；核对 Zotero 原生键盘输入仍可用，未新增快捷键。原生标签操作逐项适配；未实现或未验证的拖放、菜单等交互不得记为通过。
- 确认阅读分组仍只组织已打开视图，不会按 Zotero 分类自动创建。通过原生与 Neo 路径关闭成员后，成员立即移除且空组保留；同一 PDF 的多个视图独立，其他窗口的成员不伪装成本窗口的原生标签，跨窗口激活转到所属窗口，关闭组仅关闭当前窗口成员。
- 核对标题模板设置随位置切换保留，原生标签标题、条目标题和元数据不被改写。停用请求并完全重启后，原生标签栏和工具栏恢复；分组及标题设置仍保留。完全重启后核对原生会话恢复的视图与 `tabEnhancements.groups.v2` 关联，旧 `tabEnhancements.groups.v1` 备份未改变。
- 在隔离 profile 中验证 Main 普通模式的 `<Space>bc`／`<Space>ba`：固定发起时的目标，多 PDF 时明确选择，缺失目标显示数量。取消选择、组名、目标组或打开确认不得改变分组；确认后核对成功打开并分组的视图及结果数量，失败视图不计入。Reader／Note 不提供这两个动作，Zotero 标签、分类和元数据不受影响。

- 标签／集合操作在主窗口以 Neo 选择集为优先目标，在阅读器／笔记编辑器中使用各自上下文，操作目标和数量应清楚可解释。主窗口清除视图筛选不等于清除 Neo 选择集。
- 对一次性测试条目执行 Trash 取消，再执行确认／`u` 恢复；应能观察到对隐藏 Neo 选择集成员的拒绝，以及取消后的保存结果。阅读器中的批注删除是永久操作，仅使用一次性测试批注并检查确认。

- Plugin Manager 覆盖列表／查询／启停／设置／信息链接，以及下载前确认、固定 Translate 安装和所选插件更新；验证取消与需要重启的状态。它不能停用 Neo 自身，不提供通用商店、自动安装或卸载。

#### 引用增强（无 AI）

以下检查属于 U9；在隔离 profile 中逐项记录实际观察结果，不预填 `PASS`，也不以源码或自动化结果替代实际 Reader 操作。详细步骤见[阅读器指南](READER_GUIDE.md#查找和核对参考文献)。

- 在未设置模块偏好的新 profile 中确认 `references` 默认开启、`ai-qa` 默认关闭；工具栏**查找参考文献**和 Reader Normal 的 `<Space>fr` 只打开当前 PDF 的参考文献搜索清单。关闭 `references` 并完全重启后，预览控件、右键动作、工具栏与按键入口均不可用；Neo 热重载或重新打开 PDF 不得提前应用模块请求。另确认启动快照中没有 `references` 的旧进程保持关闭，直到完全重启。
- 使用授权且有可选中文本的 PDF，最好选没有内嵌引文链接的样本。悬停已识别的正文引文时，检查原生预览保留文献原文和链接，逐条提供**文中引用**、**本地副本**和**论文详情**；分组引文不得把第二条动作绑定到第一条。悬停不抢焦点或访问元数据服务，原生单击跳转、拖选与双击选词仍可用。
- 在正文引文或文末条目处使用原生右键菜单，核对直接动作绑定该位置；未知或歧义目标应允许搜索或人工选择，不自动选附近文献。核对清单筛选、零结果及明确编号表中的未匹配提及条目均可通过鼠标与键盘到达；出现**参考文献列表不完整**时保留覆盖警告。扫描件或没有文字层的 PDF 不做 OCR；不支持或有歧义的格式不能声称全文识别准确。
- 查看**文中引用**，核对整份 PDF 中已识别的提及、页码和原文上下文，包含非当前可见页；零个提及不代表文献未被引用。选择位置后只移动发起操作的 PDF／Reading Mode 窗格，关闭浮层并恢复可用来源的焦点；**跳转到参考文献**返回对应文末条目。本机分析不修改 PDF 或增加批注。
- 检查原生预览按钮和单项浮层的 Tab、Enter、Space、Escape、IME 与复制输入，不能被 PDF Normal 指令重处理，也不全局困住 Tab。点击外部、滚动原文或来源窗格退休时应退出并取消查询；滚动详情内的长摘要不退出。分屏、视图替换、Neo 重载与完整重启后不应遗留旧代控件、菜单或结果。
- 打开清单、筛选、定位和查找本地副本时不访问元数据服务、请求 API 密钥或调用 AI。**论文详情**只读取缓存；显式**搜索元数据**未命中缓存或点击**刷新元数据**时才请求来源，核对 DOI／标题与 Semantic Scholar、arXiv ID 与 arXiv 的对应关系。候选记录必须人工选择；显示来源、获取时间、出版信息、版本化标识符、原始摘要和缺失字段，API 计数与本地引用位置数分开。不上传 PDF 或生成 AI 摘要；关闭或更换查询后旧响应不能重新显示或抢焦点。
- 显式打开 DOI、arXiv、网页搜索、来源页和来源 PDF 时检查目标内容，不必先请求元数据，也不自动加入文库。**本地副本**可离线编辑标题或标识符检索；结果作为候选，不自动打开第一项。选择后打开已有 PDF，不更改元数据。明确添加元数据记录时，精确 DOI／arXiv 身份相同则复用，不创建重复项或覆盖内容；仅同名且身份未确认、只读或不可用文库应拒绝添加。
- 在 **Neo 设置 → 阅读器 → Semantic Scholar** 验证可选密钥的保存、空框重开与忘记；关闭设置清空草稿，论文详情不包含密钥输入。确认密钥不进入普通偏好、结果或日志；匿名查询仍可发起，但可能限流。记录实际 429／离线状态与真实在途请求取消，不自动重试。无法访问真实来源的项目记为 `NOT PERFORMED`，不要据未执行的请求填写 `PASS`。
- 在没有缓存的一次性测试配置中打开**论文详情**，确认显示“没有缓存的元数据。请搜索以获取。”且未访问元数据来源；点击**搜索元数据**后才发起查询。查询成功后完全退出并重启 Zotero，阻断元数据服务访问，再打开同一文献的详情；确认原结果可用、不发起请求，并显示来源、原始获取时间与**缓存**状态。
- 对已超过 30 分钟的缓存条目，在离线状态下用相同规范化查询再次点击**搜索元数据**；确认结果仍可用、标为**已过期**且没有新请求。只有点击**刷新元数据**才访问来源。
- 对已有缓存的条目执行显式刷新，并使本次请求失败；确认界面显示真实错误，同时保留原结果、来源、原始获取时间和缓存状态，不显示成新获取结果。
- 点击**清除元数据缓存**后完全退出并重启 Zotero，再打开相同详情；确认回到缓存未命中提示且没有自动请求，文库条目、已采纳记录和 API 密钥仍在。另在可控的在途查询中清除缓存，让旧请求结束并确认它不会重新填充缓存。

### U10：AI 问答（实验）、来源与持久成果

- 在一次性 profile 中手动启用 `ai-qa` 并完全重启 Zotero，再使用同一测试父条目下的两个不同 PDF，分别从主窗口标签页和独立 Reader 按 `<Space>aa` 打开 AI 问答。主窗口原生面板及独立工具窗显示精确附件；重复打开独立工具窗不创建第二个窗口，不改变原 PDF 的可用宽度、缩放或分屏。工具窗关闭后可重开；关闭来源 Reader 会释放其工具窗，不能借用另一个 Reader 的面板或选区。
- 配置表单显式选择 Chat Completions 或 Responses；保存、重开与取消草稿分别保留正确的协议和端点，旧配置未设置协议时仍可使用原有 Chat 服务。未知协议不能静默改用其他接口。另一个 Reader 保存配置时，当前仅修改密钥或忘记密钥的草稿仍绑定原地址；提交忘记操作只移除该端点的密钥。
- 打开与重开已存成果不发起模型请求。真实调用仅使用获准服务和测试资料，密钥在界面安全输入，不写入验收记录。区分可控协议端点与真实模型：前者可验证取消、错误和保存边界，不能替代模型对原表格、跨语言问题及无依据问题的语义验收。
- 从当前 Reader 的实际文字选区执行解释、选区问答，并从有限章节证据准备图文导引，核对请求范围与附件；章节选择本身不调用模型。默认不发图像，明确启用后只发送关联图表／表格裁图；后台或不可见的独立 Reader 也能完成裁图，不能永久停在准备状态。用显示／打印可见性相反的 PDF 图层核对裁图仍保留默认显示内容，且不改变 Reader 图层。原文、题注与模型解释分开核对。当前不读取批注、笔记或其他论文，也不自动上传整份 PDF。
- 预览只显示来源上下文／原 PDF 裁图，悬停和预览均不自动导航；确认后才跳到发起动作的精确窗格，切换活动分屏不能改写已捕获来源。未知引用或来源变化不得提供假定位，也不得保存貌似完成的结果。
- 在已存结果的来源标记、导引证据（若显示）和当前来源预览中核对实际精度均有文字说明：`文字范围`／`页面区域`（英文 `Text range`／`Page region`）；可访问名称或 `title` 也说明精度，不得只靠颜色区分。来源缺失、未知或已变化时保持状态真实；来源可定位只表示出处可回查，不表示生成论断已获语义核实。
- 慢请求显式取消不保存半成品、不自动重试。另一次请求接纳后关闭工具窗或来源 Reader，完成后重开能找到结果；不把仍在准备证据时来源已关闭的失败混作已接纳请求丢失。
- 保存人工修订并重开，核对原稿与修订分别保留。明确另存为笔记后修改该笔记，再重复采纳同一结果修订，笔记仍保留人工正文；删除本机成果不删除已采纳的笔记。批注数不因生成、预览、跳转或笔记采纳而增长。关闭 `ai-qa` 后再次开启，确认原配置、端点凭据、成果、修订与笔记 provenance 仍可用；恢复默认请求将 `ai-qa` 设为关闭。
- 在面板和工具窗实际输入问题／修订，按 U4–U7 的物理输入法与原生键要求验证，不以合成事件代替。Neo 重载和卸载后没有遗留工具窗、旧代按键处理或退休界面更新；打包安装与更新仍按 U1／U2 单独验证。


#### 固定语义核验用例：DeepSeek-OCR

固定事实基准来自 [DeepSeek-OCR: Contexts Optical Compression，arXiv:2510.18234v1 官方 HTML](https://arxiv.org/html/2510.18234v1)。下表规定允许输入、问题和应核对的事实，不是模型输出示例或验收结果。

| 用例 | 允许输入范围与问题 | 预期事实与来源锚点 | 人工判断 |
| --- | --- | --- | --- |
| 表格数值 | 仅提供 §3.2.1 的 Table 1。问：“Base 和 Large 各使用多少 vision tokens？” | Base 为 256，Large 为 400。来源：§3.2.1，Table 1。 | 两个数值与模式必须对应正确；不能把视觉 token 数说成准确率或基准成绩。 |
| Gundam 与 padding | 提供 Table 1 和 §3.2.2 的多分辨率说明段落。问：“Gundam 的局部和全局视图分别是什么分辨率？它与 Base／Large 的 padding 有何不同？” | Table 1：Base 为 1024、Large 为 1280，处理方式均为 padding；Gundam 为 `640+1024`、Gundam-M 为 `1024+1280`，处理方式为 resize + padding。§3.2.2：Gundam 由 `n` 个 640×640 局部图块和一个 1024×1024 全局视图组成，输出 `n×100+256` 个 vision tokens；原图宽、高都小于 640 时 `n=0`，退化为 Base。Base／Large 的 padding 用于保持原图宽高比，与 Gundam 的动态局部图块加全局视图不同。来源：§3.2.1 Table 1、§3.2.2。 | 核对局部／全局尺寸、模式和处理方式；特别复核此前已观察到的混淆：将 Base／Large 保持宽高比的 padding 误说成动态分辨率即判错；局部／全局尺寸互换也判错。 |
| 证据不足 | 只提供 Table 1。问：“哪个模式在 OmniDocBench 的报纸类别中编辑距离最低？” | Table 1 列出模式分辨率、token 数和处理方式，不含 OmniDocBench 类别成绩，不能从该证据得出答案。来源：§3.2.1，Table 1。 | 应明确说明现有证据不足；若猜测模式或编造指标，判为无依据回答。 |

以上用例以论文版本和语义锚点为准，不把 PDF 页码或解析器区域 ID 当作跨文件稳定标识。若实际输入使用 PDF（包括裁剪子集），在对应 PR／Issue 记录 arXiv 版本和该 PDF 完整字节的 SHA-256；页码与区域 ID 仅对该精确文件有效，不得跨版本或子集复用。实际模型调用须在对应 PR／Issue #205 记录协议、模型、原始问题、实际输入证据、原始输出与人工对照结果；不在本指南预填 PASS、虚构调用或放置示例输出。由人工对照所列来源核验，不用 LLM 自评；这些有限用例即使通过，也不代表全部语义可靠性已通过。
